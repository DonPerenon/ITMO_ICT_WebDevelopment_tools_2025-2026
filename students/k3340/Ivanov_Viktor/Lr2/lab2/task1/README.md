# Задача 1. Сумма чисел от 1 до 10 000 000 000 000

Три программы считают сумму всех целых чисел от 1 до 10¹³, разбивая диапазон на 8 параллельных подзадач.

## Файлы

| Файл | Подход |
| --- | --- |
| `threading_sum.py` | `threading.Thread` |
| `multiprocessing_sum.py` | `multiprocessing.Pool` |
| `async_sum.py` | `asyncio` + `ProcessPoolExecutor` |
| `run_benchmark.py` | Сводный локальный бенчмарк |

## Функция `calculate_sum(start, end)`

Каждая программа содержит функцию `calculate_sum()`, которая:

1. Считает сумму диапазона `[start, end]` по формуле арифметической прогрессии — прямой перебор 10¹³ элементов занял бы недели.
2. Выполняет дополнительную CPU-нагрузку (цикл из 25 млн итераций), чтобы различия между подходами были видны на замерах.

Ожидаемый результат для всего диапазона: **50 000 000 000 005 000 000 000 000**.

## Особенности подходов

### Threading

- Потоки делят один процесс и один интерпретатор Python.
- Из-за **GIL** CPU-задачи не выполняются по-настоящему параллельно — потоки по очереди получают доступ к интерпретатору.
- Подходит для I/O-bound задач (сеть, диск), но проигрывает на CPU-bound.

### Multiprocessing

- Каждый воркер — отдельный процесс со своим интерпретатором и без общего GIL.
- Реальный параллелизм на нескольких ядрах CPU.
- Выше накладные расходы на создание процессов и передачу данных.

### Async (asyncio)

- Кооперативная многозадачность в одном потоке event loop.
- Для CPU-bound задач в `async_sum.py` вычисления вынесены в `ProcessPoolExecutor`, иначе async не дал бы ускорения.
- Для I/O-bound (см. задачу 2) достаточно `async/await` без процессов.

## Замеры времени

Запуск на macOS, 8 воркеров, Python 3.13:

| Подход | Время, с | Ускорение относительно threading |
| --- | ---: | ---: |
| threading | 6.35 | 1.00× |
| multiprocessing | 1.23 | 5.16× |
| async + ProcessPoolExecutor | 1.23 | 5.18× |

## Анализ результатов

1. **Threading самый медленный** — GIL не даёт потокам одновременно выполнять CPU-код на нескольких ядрах. Время близко к последовательному запуску 8 тяжёлых задач в одном процессе.

2. **Multiprocessing и async с ProcessPoolExecutor показали схожий результат** — оба используют пул процессов для CPU-работы. Небольшая разница связана с накладными расходами event loop.

3. **Для CPU-bound задач** (математика, обработка данных) выбирают `multiprocessing` или `concurrent.futures.ProcessPoolExecutor`.

4. **Для I/O-bound задач** (HTTP-запросы, БД) — `threading` или `asyncio`; GIL отпускается при ожидании I/O, поэтому threading уже эффективен, а async — оптимален при большом числе одновременных соединений.

## Запуск

```bash
python threading_sum.py
python multiprocessing_sum.py
python async_sum.py
python run_benchmark.py
```
